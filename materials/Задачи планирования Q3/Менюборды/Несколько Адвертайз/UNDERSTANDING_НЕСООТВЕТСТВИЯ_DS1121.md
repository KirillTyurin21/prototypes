## 3. Проектное решение

### 3.1. Новый элемент «QR-код»

- Тип `qr` добавлен в `ArrivalsElementType`, палитра — категория «Информационные» (`menuboard-categories.data.ts`), иконка `qr-code` (есть в `icons.module.ts`).
- Canvas: плашка с иконкой qr-code + подпись «QR-код».
- Инспектор: общий (x/y/w/h + граница) + локальное поле «Слой (z-index)».
- Дефолт слоя при добавлении: выше всех существующих элементов.

### 3.2. Поле «Слой (z-index)»

- Новое необязательное поле `layer?: number` у `ArrivalsThemeElement`.
- Canvas: `[style.z-index]="el.layer ?? (theme.elements.length - i)"` — старые темы без layer рендерятся как раньше.
- Нормализация при загрузке: элементам без `layer` присваивается позиция в списке (+1).
- Перетаскивание списка переиндексирует слои — поведение «z-порядок по списку» сохранено.
- Advertise дефолт layer = 1 (по спеке 5.2-2).

### 3.3. Валидация сохранения (в `save()`)

1. У каждого Advertise сумма кампаний по панелям > 0, иначе блокировка с сообщением.
2. Если в теме есть QR: `advertise.layer < qr.layer`, иначе блокировка.
3. Если кампаний в справочнике нет и есть Advertise — блокировка.
4. При блокировке — проблемный элемент выделяется в инспекторе.

### 3.4. Совместимость с задачей 8 (Advertise-панели)

Кампании по-прежнему живут на уровне панели. Валидация «минимум одна кампания» считается по сумме кампаний всех панелей элемента. Подпись на canvas: «имя панели: кампании через запятую», при нуле кампаний — «Динамическая область».

## 1. Что такое «Внешний номер заказа»

### Определение

**Внешний номер заказа** — это номер заказа, присвоенный **внешней системой** (не iiko). Это идентификатор заказа в системе клиента: сайт доставки, мобильное приложение, киоск самообслуживания, агрегатор (Яндекс.Еда, Delivery Club и т.д.).

### Где хранится

Поле `ExternalNumber` в iikoWeb. Это стандартное поле сущности «Заказ» (Order), доступное через Web API.

### Зачем нужен элемент

На экране электронной очереди (Arrivals) гость видит номер своего заказа. Если заказ пришёл из внешней системы (например, доставка), гость знает свой «внешний» номер (например, №123 из приложения), а не внутренний номер iiko. Элемент «Внешний номер заказа» позволяет выводить на экран именно тот номер, который знаком гостю.

### Ключевое различие

| Аспект | Номер заказа (iiko) | Внешний номер заказа |
|--------|---------------------|----------------------|
| Источник | Генерируется iikoFront | Приходит из внешней системы |
| Пример | `#1047` | `DEL-12345`, `K-1`, `Яндекс-887` |
| У всех заказов | ✅ Да | ❌ Нет (только у заказов из внешних систем) |
| Где задаётся | Автоматически при создании | Через Web API внешней системой |

## 2. Поток данных (Data Flow)

```
┌──────────────────┐     ┌──────────────┐     ┌─────────────┐     ┌──────────────────┐
│ Внешняя система  │────▶│   iikoWeb    │────▶│  iikoFront  │────▶│ Экран эл.очереди │
│ (доставка/киоск) │     │ ExternalNumber│     │  (плагин)   │     │  (Arrivals)      │
└──────────────────┘     └──────────────┘     └─────────────┘     └──────────────────┘
        │                        │                     │                     │
   Создаёт заказ          Сохраняет заказ       Считывает заказ       Отображает элемент
   со своим номером       с ExternalNumber      из Web               «Внешний номер»
   (напр. "K-42")                               отправляет на        со значением
                                                экран Arrivals       "K-42"
```

### По шагам

1. **Внешняя система** (сайт, приложение, киоск) создаёт заказ и присваивает ему свой номер.
2. Через **iikoWeb API** заказ попадает в iikoWeb. Поле `ExternalNumber` сохраняется.
3. **iikoFront** получает заказ из Web (синхронизация).
4. Плагин Arrivals считывает заказ и отправляет данные на экран электронной очереди.
5. **Элемент «Внешний номер заказа»** на экране отображает значение `ExternalNumber`.

### Префиксы (важный нюанс)

Из обсуждения с Юрой (киоск):
- Киоск может передавать **префикс** к номеру заказа
- Это решает проблему дублирования номеров (например, касса №1 и киоск №1 могут создать заказ с одинаковым внутренним номером)
- Префикс передаётся в iikoWeb → становится частью ExternalNumber
- Пример: киоск с префиксом `K` → ExternalNumber = `K-1047`

## 3. Ключевые решения встречи 11.06.2026

### 3.1. Отдельный новый элемент (НЕ модификация существующего)

**Дискуссия:**
- **Кирилл** предлагал: добавить галочку «Использовать как внешний номер» в существующий элемент «Номер заказа»
- **Михаил** возразил: много источников (Яндекс, Магнит, киоски и т.д.) — у каждого свои требования. Обычным пользователям, которым внешний номер не нужен, не надо усложнять интерфейс
- **Руслан** поддержал Михаила

**Решение:** ✅ **Новый отдельный элемент** «Внешний номер заказа». Не модифицируем существующий.

**Цитата (Руслан, 01:06:54):** «Да нет, новый элемент у нас очень быстро создается. Давайте остановимся на новом элементе.»

### 3.2. Размещение — раздел контролов электронной очереди

Элемент добавляется в **раздел контролов** (Controls) электронной очереди. Это НЕ базовый элемент (как текст/изображение), а специализированный контрольный элемент данных.

### 3.3. Источник данных — ExternalNumber из Web

**Встреча с Ваней (02_27 PM):**
- Источник: поле `ExternalNumber` в iikoWeb
- Это номер, который **клиент передаёт свой собственный** (не iiko-вский)
- Если у заказа есть ExternalNumber → отображается в элементе
- Если нет → поведение уточняется (обычный номер или пусто)

### 3.4. Настройки — через системные настройки

- Настройка **источников** (source) — галочками: для каких источников выводить внешний номер
- **Не на уровне терминала** (Руслан: «пока не надо»)
- Настройки форматирования: длина символов, лидирующие символы (уже существуют в системных настройках)

### 3.5. Что НЕ делаем (важные отрицательные решения)

| ❌ Не делаем | Почему |
|-------------|--------|
| Не модифицируем существующий «Номер заказа» | Чтобы не усложнять для тех, кому внешний номер не нужен |
| Не привязываем настройки к конкретному терминалу | Пока нет сценариев, требующих этого |
| Не дублируем настройки в элемент | Настройки — в системных настройках, элемент только отображает |

## Приложение В: Что говорит iikoWeb (из локализации стенда)

Из файла локализации стенда (`polyfills.*.js`):

```
maskOrderExternalNumberDescId: "Внешний номер заказа (например, номер заказа на сайте или в приложении)"
```

**Английская версия:**
```
maskOrderExternalNumberDescId: "External order number (for example, the order number on the website or in the app)"
```

Это подтверждает, что поле `ExternalNumber` — стандартное поле заказа в iikoWeb, используемое для отображения на экранах (в контексте «масок» — настроек отображения данных заказа на экране).

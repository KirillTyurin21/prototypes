## 1. Назначение и бизнес-цель

Доработка Angular-фронтенда iikoWeb. В редакторах контролов и тем продуктов Digital Signage палитра элементов реорганизуется из плоского списка в аккордеон с семантическими категориями, иконками и поиском.

**Продукты:** Arrivals (Электронная очередь), Customer Screen (Экран покупателя), MenuBoard (Доска меню), Киоск (Kiosk).

**Проблема:** десятки элементов в палитре идут подряд без группировки -- "простыня". Администратор долго ищет нужный элемент.

**Цель:** сократить время поиска элемента через визуальную группировку по категориям с иконками и поиском.

### 1.1. Объём работ

#### MVP

| # | Функция | Описание |
|---|---------|----------|
| 1 | Группировка элементов по категориям | В каждой панели "Добавить элемент" плоский список заменяется на аккордеон с семантическими категориями. Категория: иконка + название + счётчик + шеврон |
| 2 | Иконки категорий и элементов | Каждая категория и каждый элемент получают иконку Lucide |
| 3 | Поиск по элементам | Поле ввода над категориями -- живой фильтр по названию элемента. Чисто на фронте |
| 4 | Resize боковой панели | Пользователь может изменять ширину панели "Добавить элемент", перетаскивая левую границу |

#### Вне scope

| Функция | Причина |
|---------|---------|
| Перенос модели категорий на backend | Только frontend, хардкод-конфигурация в Angular |
| Создание новых иконок | Используются существующие иконки Lucide |
| Изменение логики добавления элемента на canvas | Группировка -- чисто визуальная доработка |

> **Источник решения о поиске:** стенограмма встречи 11.06.2026.
> **Источник решения о resize:** стенограмма встречи 23.07.2026 (Кирилл, 12:59; Руслан, 13:08).

## 2. Текущее состояние

В каждом редакторе (контролов или тем) при нажатии "Добавить элемент" открывается панель с плоским списком всех доступных элементов. Элементы не сгруппированы, иконок нет. Элементы захардкожены в Angular, backend не управляет их перечнем.

## 3. Целевое решение

### 3.1. Общая схема

Группировка применяется в каждой панели "Добавить элемент" независимо -- для каждого редактора своя конфигурация категорий:

| # | Продукт | Редактор | Тип контрола | Элементов | Категорий |
|:-:|---------|----------|:----------:|:---:|:---:|
| 1 | Arrivals | Темы | -- | 8 | 4 |
| 2 | Arrivals | Контролы | -- | 28 | 7 |
| 3 | Customer Screen | Темы | -- | 31 | 7 |
| 4 | Customer Screen | Контролы | Стандартный | 15 | 3 |
| 5 | Customer Screen | Контролы | Подсказка | 10 | 3 |
| 6 | MenuBoard | Темы | -- | 7 | 4 |
| 7 | MenuBoard | Контролы | -- | 28 | = Arrivals (п.2) |
| 8 | Киоск | Темы | -- | 11 | 4 |

**Аккордеон:** каждая категория: иконка + название + счётчик (N) + шеврон. Первая категория раскрыта по умолчанию, остальные свёрнуты. Клик по заголовку -- раскрытие/сворачивание с анимацией.

**Поиск:** поле ввода над категориями, иконка `search`, кнопка очистки (x). Фильтрация по названию элемента, без учёта регистра. Категории без совпадений скрываются. Пустой результат -- текст "Ничего не найдено". Чисто на фронте.

## 5. UI

Панель "Добавить элемент" -- едина для всех редакторов. Отличается только набором категорий и элементов внутри аккордеона.

| Область | Описание |
|---------|----------|
| Заголовок | "Добавить элемент" + кнопка закрытия (x) |
| Поиск | Поле ввода с иконкой `search` и кнопкой очистки |
| Аккордеон | Категории с иконками, названиями, счётчиками (N) и шевронами |
| Resize | Пользователь может расширить панель, перетаскивая левую границу. Минимальная ширина -- 300px, максимальная -- до ширины canvas |

**Элемент категории:** `[иконка] Название (N) [шеврон]` -- кликабельный заголовок.
**Элемент внутри:** `[иконка] Название` -- отступ слева, hover-подсветка, cursor pointer.

## 6. Модель данных (frontend)

Хардкод-конфигурация в Angular (TypeScript-константы).

### 6.1. Структура данных

```typescript
interface ElementItem {
  type: string;       // Тип элемента (enum-значение)
  label: string;      // Название на русском
  icon: string;       // Иконка Lucide
}

interface ElementCategory {
  id: string;           // Уникальный ID категории
  label: string;        // Название категории на русском
  icon: string;         // Иконка Lucide
  collapsed: boolean;   // Свёрнута по умолчанию (true для всех кроме первой)
  elements: ElementItem[];
}
```

### 6.2. Конфигурации

| Константа | Где используется | Категорий | Элементов |
|-----------|-----------------|:---:|:---:|
| `ARRIVALS_THEME_CATEGORIES` | Arrivals -> Темы | 4 | 8 |
| `ARRIVALS_CONTROL_CATEGORIES` | Arrivals -> Контролы | 7 | 28 |

## 7. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Поиск не дал результатов | Текст "Ничего не найдено" |
| Категория без элементов | Не отображается в палитре |
| Иконка не найдена в пакете Lucide | Элемент/категория без иконки, `console.warn`. Работа конструктора не нарушается |

## 9. Ограничения

- Конфигурация категорий захардкожена в Angular. Новый тип элемента = ручное обновление констант + сборка фронтенда
- Поиск фильтрует только по названию элемента, не по названию категории
- Состояние раскрытия категорий не сохраняется между сессиями
- MenuBoard Controls = ссылка на Arrivals Controls. Изменение в Arrivals автоматически применяется к MenuBoard

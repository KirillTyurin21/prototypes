# Отчёт-аудит: элемент «Динамическая область» (Доска меню) глазами простого пользователя

> **Дата:** 2026-09-10
> **Что аудировалось:** прототип `web-screens`, экран «Доска меню → Редактор темы» (`menuboard-theme-editor/101`), элемент «Динамическая область», а также раздел «Кампании».
> **Точка зрения:** пользователь, который раньше назначал на рекламный блок «Компанию», а теперь должен работать с «Рекламными кампаниями».
> **Эталон:** боевой стенд `stand3-iikoweb` (`#/campaign`) + дизайн-система `frontend-common.iiko.ru/components/categories`.
> **Статус:** аудит. Код НЕ менялся — ждёт решения Кирилла о переделке.

---

## 1. Резюме (TL;DR)

Элемент переделан по спеке DS-1121 формально верно: Но **с точки зрения пользователя прототип сейчас не готов к показу** — в нём есть один сквозной разрыв, который «убивает» всю историю:

> **Пользователь создаёт кампанию в разделе «Кампании» (с папками, как на стенде), а в «Динамической области» её НЕ видит.** Список кампаний в области — это 4 захардкоженных мок-кампании, никак не связанные с разделом «Кампании».

Плюс к этому — потеряна структура **папок** (о чём вы и сказали) и ряд мелочей, которые делают экран непонятным для «глупого» пользователя.

**Вывод:** переделка нужна, но не «точечная», а связная — сначала связать данные («Кампании» ↔ область), затем вернуть папки, затем докрутить UX по дизайн-системе.

## 2. Как это работает на стенде (эталон)

### 2.1 Раздел «Кампании» (`#/campaign`)

Проверено в браузере на `stand3-iikoweb` (ver 9.6.4.367281):

- Шапка: заголовок «Кампании» + кнопки **«Создать папку»** (иконка папки) и **«Добавить»** (иконка файла).
- Таблица: **Название | Период действия | Время действия | Разрешение | Действия**.
- Строки двух видов:
  - **Папка** — иконка папки + имя (клик → внутрь папки), действия: редактировать / удалить / переместить.
  - **Кампания** — имя + период + время + разрешение, действия: редактировать / удалить / переместить.
- Папки — **реальная иерархия** (вложенность, навигация «..» вверх, перенос элемента в папку через диалог «Переместить элемент»).

**Важно:** на стенде папки ЕСТЬ и работают. Кампании группируются в папки — это основной способ наведения порядка при десятках кампаний.

> Примечание: `stand3-iikoweb2` напрямую не открылся (требует отдельной авторизации, 401). Но по `stand3-iikoweb` и по вашим словам требование однозначное: **папки у кампаний должны быть**.

### 2.2 Назначение кампаний

- **Кампания = медиаплан**: ролики/картинки + период + время + дни недели + разрешения + режимы экрана.
- На стенде кампания назначается **на терминал** (колонка «Кампании» в настройке терминалов, одиночный выбор).
- Для **Доски меню** по DS-1121 назначение переносится **внутрь темы** — на элемент «Динамическая область» (мультивыбор кампаний).

### 2.3 Что берём за эталон

| Аспект | Эталон со стенда |
|---|---|
| Организация кампаний | **Папки** (иерархия, «Создать папку», «Переместить») |
| Кампания | Название + период + время + разрешение |
| Назначение | В Доске меню — внутри темы, на область, **мультивыбор** |
| Дизайн | `frontend-common.iiko.ru/components/categories` |

## 3. Как это сейчас в прототипе

### 3.1 Раздел «Кампании» (`/prototype/web-screens/campaigns`)

- Папки **есть** («Создать папку», навигация, диалог «Переместить»). Реплика стенда сделана.
- Кампании хранятся в `CampaignsDataService` (localStorage, ключ `campaigns.v3`), папки — `campaignFolders.v2`.

### 3.2 Элемент «Динамическая область» (`menuboard-theme-editor/101`)

Инспектор элемента (проверено в браузере):

```
Рекламные кампании
├── [Поиск по названию]
├── Новогодняя (01.01.2026 - 31.01.2026)
├── Летнее меню (01.06.2026 - 31.08.2026)
├── Осенние скидки (01.09.2026 - 30.11.2026)
├── Сезонное предложение (01.03.2026 - 31.05.2026)
├── «Выбрано кампаний: 1»
└── «Кампании — медиаплан с расписанием из раздела Кампании»

Макет   (сворачивается)
Граница (сворачивается)
```

Ключевой факт из кода: список кампаний области — это `campaignOptions`, **жёстко заданный массив из 4 мок-кампаний** прямо в компоненте. `CampaignsDataService` (реальный справочник кампаний с папками) в редактор темы **не подключён вообще**.

## 4. Проблемы — от лица «простого глупого пользователя»

Легенда: пользователь заходит «с улицы», не читал спеку. Раньше он назначал «Компанию». Теперь ему говорят «работай с кампаниями».

### 🔴 P1. Кампании из раздела «Кампании» не видны в области (критично)

**Сценарий:** пользователь создал кампанию «Новая кампания 1» в разделе «Кампании». Открывает тему, добавляет «Динамическую область», раскрывает «Рекламные кампании» — и видит 4 чужих названия («Новогодняя», «Летнее меню»…), а своей кампании **нет**.

**Причина:** список в области захардкожен (`campaignOptions`), не читается из `CampaignsDataService`.

**Последствие:** вся история прототипа ломается — «создал → назначил» не работает.

### 🔴 P2. Названия кампаний в области не совпадают с разделом «Кампании» (критично)

В области: «Новогодняя», «Летнее меню», «Осенние скидки», «Сезонное предложение».
В разделе «Кампании»: «Новая кампания 1», «Летняя акция», папка «Сезонные акции» и т.д.

Пользователь видит два разных мира с одинаковым названием раздела — недоумение.

### 🟠 P3. В области потеряны папки (прямое замечание пользователя) (важно)

На стенде кампании лежат в папках. В области — плоский список. При 20–50 кампаниях в папках пользователь не может быстро найти нужную (только поиск по точному названию).

**Что нужно:** группировка кампаний в селекторе по папкам (дерево «папка → кампании») или хотя бы заголовки-секции по папкам.

### 🔴 P4. Термин «Динамическая область» непонятен (критично для юзабилити)

Пользователь не понимает, что это: «область чего?». Ни в палитре, ни в инспекторе нет человеческого описания «это окно на экране, где крутится реклама».

**Что нужно:** короткое описание элемента в палитре и/или в инспекторе. Например, подпись-пояснение: «Место на экране менюборда, где по расписанию показываются рекламные кампании».

### 🟠 P5. Нет действия «Создать кампанию» прямо из области (важно)

Сценарий: в области пусто / нужной кампании нет. Сейчас пустое состояние просто говорит «Создайте кампанию в разделе Кампании», но не ведёт туда.

**Что нужно:** ссылка-действие «Создать кампанию» (переход в раздел «Кампании» или открытие формы создания), по паттерну пустых состояний DS.

### 🟠 P6. Нет «Выбрать все» (важно)

В DS (`@iiko/select-list`) есть готовый паттерн `resto-select-all-toggle` («Все» + трёхстадийная галочка). В области его нет — при 20 кампаниях выбор по одной утомляет.

### 🟠 P7. Чекбоксы — не настоящие чекбоксы (важно, accessibility)

В коде это `<label>` + `<span>`. Последствия:
- нельзя выбрать с клавиатуры (Tab/Space),
- нет состояния indeterminate,
- нет aria-семантики,
- скринридер не читает как чекбокс.

**Что нужно:** компонент `RestoCheckbox` (`@iiko/ui-kit/checkbox`) — три состояния, клавиатура, формы, accessibility.

### 🟡 P8. Пустые состояния без иконки и призыва к действию (желательно)

«Кампании не выбраны», «Ничего не найдено», «Нет доступных кампаний» — голый текст. По DS пустое состояние = иконка + текст + кнопка действия.

### 🟡 P9. Подпись на канвасе нечитаема при нескольких кампаниях (желательно)

Канвас подписывает область всеми названиями через запятую («Новогодняя, Летнее меню, Осенние скидки…»). При 3+ кампаниях — каша. DS-1121 (6.2) требует «названия через запятую», но на канвасе разумнее: «3 кампании» (счётчик) + полный список в тултипе/инспекторе.

### 🟡 P10. Счётчик «Выбрано кампаний» оторван от списка (желательно)

При длинном списке счётчик внизу не виден. Лучше закрепить его в заголовке секции или сразу под полем поиска.

### 🟠 P11. Ошибки — только toast при сохранении, а не у поля (важно)

«Выберите хотя бы одну кампанию» появляется тостом по нажатию «Сохранить», само поле при этом не подсвечено. Пользователь не видит, ЧТО исправить. По DS — инлайн-ошибка у поля (красная рамка/подпись).

### 🟠 P12. «Слой (z-index)» и «ниже QR-кода» — технический жаргон (важно)

Правило «Динамическая область должна быть ниже QR-кода» — правильно, но сформулировано для разработчика. Пользователь не знает, что такое z-index и почему область должна быть ниже QR.

**Что нужно:** переформулировать по-человечески: «Слой» → «Порядок отображения» (выше/ниже), а подсказку — «Область рекламы должна отображаться под QR-кодом, чтобы код оставался кликабельным».

### 🟠 P13. Стилистика инспектора не полностью по DS (важно)

- Поля/поиск/чекбоксы/кнопки — кастомные, а не DS-компоненты.
- Тосты (`#424242` на всю ширину снизу) — по DS это snackbar с конкретными параметрами.
- «Макет»/«Граница» — свои сворачиваемые секции; в DS есть готовые паттерны (Card, Stepper/аккордеон).

## 5. Решения (что сделать, со ссылками на дизайн-систему)

### Решение к P1–P3 (сквозное): связать данные и вернуть папки

1. **Подключить `CampaignsDataService` в редактор темы.** Список кампаний области брать из `campaigns` сервиса (те же, что в разделе «Кампании»), а не из захардкоженного массива.
2. **Вернуть структуру папок в селектор.** Кампании группировать по папкам (`folderId` + `CampaignFolder`). Два варианта:
   - **Вариант A (рекомендуется):** дерево «папка → кампании» с раскрытием папок и чекбоксами (в духе DS `tree-table` / `select-list`). Папка — заголовок секции, внутри — кампании-чекбоксы. Это 1:1 со стендом и решает ваше замечание про папки.
   - **Вариант B (проще):** плоский список с заголовками-секциями по папкам («Корень», «Сезонные акции», …).
3. **Кампании без папки** — в корне (секция «Без папки» или просто первыми).

### Решение к P4–P5 (понятность и действия)

4. В палитре и/или инспекторе добавить **человеческое описание** «Динамической области», а под заголовком «Рекламные кампании» — короткий хелп: *«Здесь выбираются рекламные кампании (ролики с расписанием), которые будут крутиться в этом окне»*.
5. В пустом состоянии и при отсутствии кампаний — **действие «Создать кампанию»** (переход в раздел «Кампании»).

### Решение к P6–P8 (список выбора по DS)

6. Добавить **«Выбрать все»** — паттерн `resto-select-all-toggle` из `@iiko/select-list`.
7. Заменить кастомные чекбоксы на **`RestoCheckbox`** (`@iiko/ui-kit/checkbox`).
8. Пустые состояния оформить с иконкой + текстом + действием (DS Empty state).

### Решение к P9–P10 (канвас и счётчик)

9. На канвасе при 2+ кампаниях подписывать **«N кампаний»**; полный список — в тултипе/инспекторе. (При 1 кампании — её название.)
10. Счётчик вынести в заголовок секции «Рекламные кампании (N)» и/или закрепить под поиском.

### Решение к P11–P12 (валидация и термины)

11. Валидацию показывать **инлайново у поля** (красная подсветка + текст), а не только toast при сохранении.
12. Переименовать «Слой (z-index)» → **«Порядок отображения»**; подсказку — по-человечески («под QR-кодом»).

### Решение к P13 (дизайн-система)

13. Привести инспектор к DS: кнопки `Button` (`@iiko/ui-kit`), поля `Input`/`Input number`, тосты-снакбары, аккордеоны секций. Токены — из `frontend-common` (`--resto-*`): primary `#448AFF`, текст `#333`, caption `#616161`, stroke `#D6D6D6`, шапка таблицы `#F0F5FF`, радиусы 4/8, шрифт Roboto.

### Соответствие компонентов DS (шпаргалка)

| Что нужно | Компонент DS |
|---|---|
| Чекбокс кампании (3 состояния, клавиатура) | `RestoCheckbox` (`@iiko/ui-kit/checkbox`) |
| Мультивыбор + «Выбрать все» | `select-list` (`@iiko/select-list`) + `resto-select-all-toggle` |
| Дерево «папка → кампании» | `tree-table` (`@iiko/table`, `serializeTreeNodes`) |
| Поиск | `Shell: Search` / стандартное поле DS |
| Кнопки | `Button` (`@iiko/ui-kit`) |
| Пустые состояния | паттерн Empty state (иконка + текст + действие) |
| Ошибка поля | инлайн-валидация (красная рамка + текст `#FF5252`) |
